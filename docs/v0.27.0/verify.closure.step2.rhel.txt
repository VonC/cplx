         digest makes two parties agree on the bytes and not on their meaning,

         every party. Seventeen refusals are driven, each naming its own record

         a TRAILING empty field, a multi-segment subdirectory, an out-of-order
         root record and a wrong version line. Each mutates ONE record of a valid
         base document that parses clean, which is the control for all of them.

  ORDERING IS SIGNIFICANT FOR `root` AND FOR NOTHING ELSE, WHICH THE FORWARD
         CASES MEASURE RATHER THAN THE PROSE CLAIM. A `subdir` record placed
         BEFORE the `root` it names is accepted and its subdirectory is RETAINED
         in the parsed model, which `step2/forward/subdir-before-root-retained`
         asserts by reading the model back as `python=current`. A second such
         record naming the same pair is refused as a duplicate whether or not
         its root has been read yet. Both cases were added in round 1, and the
         acceptance-only half of the first would have passed against a parser
         that accepted the record and silently dropped its subdirectory.

  DECODING PRECEDES DOMAIN VALIDATION, AND THE REFUSAL REASON IS THE PROOF. The
         pair is what shows it, never either half. A field carrying %2F is
         refused as an UNDEFINED ESCAPE and never reaches its domain; a field
         carrying the defined %7C is decoded first and then refused BY THE
         DOMAIN, naming the decoded value `libc|so.6`. Reversing the order would
         have refused the second on its raw text, and would have let a %2F pass
         a no-slash domain and become a separator afterwards.

WHY THE DIGEST DOMAIN GETS ITS OWN CASES. The domain is the part a second
         implementation gets wrong, so it is driven rather than described: the
         same declaration written with CRLF endings produces a DIFFERENT digest,
         because no normalisation pass exists and a line ending is content; and
         byte-identical bytes read through a different path produce the SAME
         one, because the domain is the content and never the location, which is
         what lets the archive and cplx reach the same value from two trees. The
         CRLF case carries its own control, that the CRLF document still
         digests, so the difference is about bytes rather than about one of the
         two files being empty.

WHY THE BUNDLE IS READ BEFORE ANYTHING ELSE. A check evaluated against a
         declaration nobody can vouch for is worth less than no check at all, so
         a bundle that is absent, substituted or corrupted refuses before any
         invariant runs. The assertion is the ABSENCE of every typed scope line
         and not the exit code alone: a checker that refused and still
         classified would have answered a question against a declaration it had
         already rejected.

===== round 1 repairs, and what they superseded =====

The submission run of this step was green, at 85 cases and 0 failures on this
same host, and it was green over two real parser defects. The code review found
both, repaired both inside the existing module boundary, and added six
assertions that fail against the submitted parser. Recording that here is the
point of a retained capture: a green run over a defect is exactly the shape a
later reader has to be able to see.

  DEFECT 1, A SUBDIRECTORY DECLARED BEFORE ITS ROOT WAS ACCEPTED AND DROPPED.
         `closure_cfg_subdir` appended to the root's comma-fenced list only when
         that root was ALREADY declared, while the cross-reference pass validated
         the same record against the complete set. So `subdir|python|current`
         above `root|python` returned success and produced `python=`, silently
         changing the declared candidate shape although only root ordering is
         significant, and this file's own module header claimed the opposite. A
         duplicate forward pair was accepted for the same reason. The repair
         keeps the subdirectory operand in the existing cross-reference entry and
         applies it, with the duplicate test, once every root is known.

  DEFECT 2, A TRAILING SEPARATOR WAS DISCARDED BEFORE THE FIELD COUNT WAS READ.
         `IFS='|' read -r -a` drops a final empty field, so `root|python|` split
         into two fields and passed the two-field root record check, and
         `floor|libc.so.6|any|` passed the three-field one. The same lexer
         admitted malformed envelope records. The repair refuses a trailing
         separator before splitting, which is where a lexical rule belongs.

Both were verified closed against the repaired module by direct reproduction as
well as by the suite: the forward pair now yields `python=current`, the duplicate
forward pair refuses at its own line, and both trailing-separator forms refuse as

/etc/os-release, so the `any-linux` gate reports UNANSWERED by design rather than
