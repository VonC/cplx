This is the RHEL half of the step 2 evidence, and it is the only half that can
exercise both engines at the mirror, because it is the only supported target
where rsync exists to be chosen against.

**The boundary, which is the point of this step.** Two shapes are refused and
both refusals are here. A destination that is a regular file fails at exit 5 with
the reworded diagnostic, and its content is byte-identical afterwards, so the
refusal preceded any delete. A destination that is a symlink onto an external
directory fails the same way, and `step2 external target intact` confirms the
external tree kept both its visible and its hidden entry.

That second case is the one worth pausing on. The design records M1 measuring the
rsync path following exactly that shape under `--delete`, emptying the external
target and returning 0. The fallback refuses it. On the destination where the two
engines differ most, the new engine is the safe one, and this capture is the
first time that has been shown on a target rather than argued from a measurement.

**The mirror itself.** A fresh fallback install completes at exit 0 with the cp
engine read from the run trace, the archive's hidden entry carried into the tree,
and the canary SONAME symlink still a link, which the post-state oracle asserts.
A redeployment over a populated tree removes every stale entry, hidden, visible
and directory alike. The hidden one matters most: a copy form that depended on
the caller's globbing would have left it, and it would not have shown in a
listing.

**Both engines fail the same way on a bad destination.** `step2 dest regular
file` runs the fallback and `step2 rsync dest regular file` runs rsync on the
same fixture; both exit 5 with a message naming the mirror step and their own
engine. The exit code did not move, so no caller changes, which is the whole
reason the plan assigned the rewording to this step rather than a later one.

**The transition marker moved rather than vanished.** `step1 forced still
operates rsync` is gone and `step1 forced now operates cp` is here in its place,
passing. Step 1 recorded that a forced selection still operated rsync; step 2
closes that gap, and the assertion follows the behaviour instead of being
deleted with it.
