This is the RHEL half of the step 3 evidence, and the only half that can run both
engines at both transfer sites in one pass.

**The case that had never run anywhere.** `step3 dest symlink to file` refuses at
exit 7, `step3 symlink left intact` shows the link itself was not replaced, and
`step3 external target intact` shows the file it pointed at is byte- and
mtime-identical. M2 measured this engine following such a link, overwriting the
external target and returning 0: silent data loss reported as success. Until this
run, everything said about that refusal came from reading the code. It is now
measured on a target.

**The Step 0 gate closes here.** `step3 dest FIFO refused promptly` returns exit
7 with the FIFO intact. At step 0 the same shape was rsync replacing it at exit
0, and M2 measured this engine blocking on it. Promptly is falsifiable rather
than rhetorical: the case runs under the twenty-second watchdog, so a blocking
engine would return 124 and fail the expected 7, and the calibration control two
sections above still reports its own timeout.

**The deploy site is asserted from its own trace.** `step3 accepted deploy engine`
reads `Deploy engine cp:` and requires two occurrences, one per archive root
file. The earlier version of this assertion read the mirror's marker, which on
this host would have passed for step 2's behaviour, cp at the mirror and rsync at
the deploy site. That is the state step 3 exists to move past, so the assertion
had to be able to reject it, and it does: run against the step 2 installer it
fails with "no Deploy engine cp: trace".

**Both engines, and where they deliberately differ.** `step3 rsync dest symlink
to file` completes at exit 0 and `step3 rsync replaced the link` confirms rsync
replaced the link while leaving the external target alone. The fallback refuses
the same shape. That asymmetry is the design's choice, asserted here rather than
assumed, and it is the same trade as the mirror boundary: the new engine is the
stricter one.

**Directories are refused whether empty or populated**, and the populated one
keeps its content, so the refusal costs nothing that was there.

round 1 run since only the harness moved. The harness whole-file digest
`23be347e` pins this capture to the staged cplx source; the shared-body digest
`5e0f4430` is the value the Debian capture also reports.
