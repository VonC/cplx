===== the fixture engine, which is what makes the run possible =====

Plan decision Q07 fixes the mechanism: mutate donor objects found on the host,
after validating the donor's ELF class and section shape, and assert the mutated
semantic result before any case may use the object. The engine landed with this
step and its mechanism is recorded in the corpus header beside the rows:

  the name slots     the LAST 256 bytes of the donor's own .dynstr, taken as four
                     64-byte slots. A mutation writes its name into a slot and
                     repoints one dynamic entry at that offset, so no fixture
                     name is bounded by the length of the string it replaces. The
                     bytes it overwrites are symbol names, which nothing in this
                     effort reads.
  the spare slot     the linker pads .dynamic past its terminating DT_NULL.
                     `needed-add` turns the FIRST DT_NULL into a real DT_NEEDED
                     and leaves the next spare slot as the terminator, so the
                     need is ADDED rather than substituted for another.

Both are DONOR REQUIREMENTS carried in the corpus donor row, not assumptions: a
donor that cannot supply either is refused before a fixture is generated from it.
Measured on this host, every candidate library carries four spare DT_NULL slots
and a .dynstr well past the 512-byte floor, and /usr/lib64/libz.so.1 is the first
that validates.

The corpus gained sixteen rows for this step, each because a case would otherwise
have proved something narrower than it claims: `provider-donor-need`, without
which every generated subject would also refuse on the donor's own libc and the
planted defect would be one refusal among several; `provider-first-libssl`,
without which "absent from the provider index" would hold for the wrong reason;
`subject-need-provider`, which is the one subject an edge reaches and so the
negative control the unreferenced finding needs; from round 1 of the code review,
`reader-needed-value-unreadable` and `subject-libssl-consumer`, which give the
two reproduced false-green paths a fixture apiece; and from round 2,
`provider-alias-target`, `provider-alias-link` and `subject-alias-consumer`, the
ordinary `libz.so.1 -> libz.so.1.2.11` layout that a name-keyed alias test
reports as an unreferenced library.

`needed-offset-corrupt` is the round 1 verb, and it is worth naming because of
what it does NOT touch: it repoints the first `DT_NEEDED` VALUE past the end of
the string table and leaves the table itself alone. A supported reader then exits
0 and prints the raw value with no brackets, which is the shape that made a
bracket-only parser drop the entry.

The submission run of this step was green, at 69 cases and 0 failures on this
same host, and it was green over three defects. The code review reproduced all
three independently; recording that here is the point of a retained capture,
because a green run over a defect is exactly the shape a later reader has to be
able to see.

  R1  A FAILED TRAVERSAL READ AS AN EMPTY TREE. The walk ran `find` inside a
      process substitution, which discards the exit status, so a directory the
      account cannot read held its shipped objects out of the listing while the
      run printed `CLOSURE MEMBERSHIP OK` and exited 0. A finder that returned 1
      produced the same green over a completely unwalked tree. The listing now
      goes through a temporary file so the status is collected, and an
      incomplete walk is a typed `UNDETERMINED|traversal|` that makes the run
      non-passing on its own. It stays ONE `find` invocation, which the
      instrumented case still measures.
  R2  A RECOGNIZED RECORD WHOSE VALUE COULD NOT BE READ WAS DROPPED. The parser
      matched only the bracketed shape, so a `DT_NEEDED` whose string offset
      falls outside the string table, printed by a SUPPORTED reader at status 0
      as a raw value with no brackets, left the object recorded with an empty
      dependency set that resolved nothing and refused nothing. The parser now
      refuses the whole object and names the field, and it commits its counters
      only on success, so a refused output leaves no partial edge count behind.
  R3  REACHABILITY WAS KEYED BY NAME RATHER THAN BY RESOLVED PATH. A consumer
      naming `libssl.so.3` marked BOTH copies reached, so the second copy under
      `root/usr/bin`, which is the subject the design distinguishes from a
      provider, was never reported. An edge now reaches the ONE path the
      observed scope selects for that name, with an `-ef` test against the
      selected path of the subject's own basename for the alias case. The
      result is renamed `UNREFERENCED-BY-EDGE`, because the design's finding is

      reader who took this list for the design's finding would read a shipped

  R5  A SYMLINKED DIRECTORY IN THE SELECTED PATH WAS NOT RESOLVED. The link map

===== round 5 repair, and the obligation still open =====

Round 5 found the component walk still wrong in three ways, all of them the same
obligation seen from different angles, and all reproduced with real files.

  R5 again  A LINK TARGET IS A PATH, NOT A DESTINATION. The component loop
            substituted a target WHOLE and then asked only whether that whole
            target was another link, so a component INSIDE the target was never
            resolved. The reader also reduced `..` lexically when it recorded the
            target, before the components before it had been expanded, and `..`
            applies to the directory the resolution actually REACHED. And the
            hop bound cached a partially chased path as though it were physical.
            The resolution is now the filesystem's own: components are taken one
            at a time from a queue, a link's target is SPLICED BACK INTO that
            queue rather than taken whole, an absolute target restarts from the
            root, and `..` pops the directory reached so far. The reader records
            the raw target and reduces nothing. A chase that exceeds the bound is
            typed UNDETERMINED and NOTHING is cached.

            The bound is the kernel's own SYMLOOP_MAX rather than a number this
            effort invented, because nothing in the plan says how deep a valid
            chain may be and a nine-link chain resolves on the supported host.

            half this step does not own.

===== the amendment that closed R3b =====

R3b was never an implementation defect: the reviewed plan carried two lines that

  design Q13   the finding has two halves with separate inputs. The edge half is
               computed from the collected edges and reported as
