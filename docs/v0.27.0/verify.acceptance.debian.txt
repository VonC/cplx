exists for.

**The row only this target can produce.** `accept no-rsync host selection` reads
"selected cp ... rsync not found on PATH": the fallback was chosen because rsync
is genuinely absent, not because the override forced it. `accept no-rsync host
engine` then shows cp actually operated, and `accept no-rsync host installs`
shows the install completed. On RHEL the fallback can only ever be reached under
CPLX_INSTALL_PKG_FORCE_CP, so no RHEL run can stand in for this one.

**The interrupted copy runs here now, and that is the point of it.** In build 51
it did not: the row had been placed inside the two-engine section, so it ran only
where rsync exists. It is a property of the fallback engine rather than a
comparison between engines, and this agent is where the fallback is the only
engine there is, which makes a copy cut short here a real recovery rather than a
forced one. The override is set only where rsync is present, so this run measures
the engine the agent would actually use. Exit 5 at the mirror, a partial tree
with staging retained, then 2 entries to 9 after the rerun.

**What this capture does NOT claim.** The equivalence pair, the canary and loader
comparisons and the rsync-failure row need two engines on one host and cannot run
here. The harness prints that in the output rather than omitting the rows. Before
that branch existed, a step 5 run on this agent would have skipped all of them in
silence, run the single gzip case, and been eligible to print "every assertion and
every negative control behaved as designed".

**Seven oracle controls run here too.** Two drive the equivalence oracle and five
the loader verdict, all with fabricated inputs, so none of them needs rsync. All
seven refuse. This agent therefore confirms the oracle behaviour the RHEL capture
depends on, including the five loader refusals no real archive can produce, since
a real archive only ever exercises the accepting branch.
