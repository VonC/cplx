This is the capture the whole effort was aimed at. `baseline no-rsync mirror`
passes at **exit 0** on a host with no rsync at all, which is the Q19 defect gone
end to end, measured where it actually bites.

**Read that one case across four captures.** At step 0 it asserted exit 5 at the
mirror with nothing deployed: the defect written down. At step 2 it asserted exit
7 at the root-file site under `mirrored-not-deployed`: the mirror fixed, the
deploy not. Here it asserts exit 0 under `installed`. Three different meanings,
one assertion, re-pointed each time rather than deleted, which is the only reason
that progression is legible at all.

**The deploy site is asserted from its own trace.** `step3 accepted deploy engine`
reads `Deploy engine cp:` and requires two occurrences, one per archive root
file. The earlier assertion read the mirror's marker, which proves only that the
mirror used cp and would have passed for step 2's behaviour on a host with rsync.
That is the state step 3 moves past, so the assertion had to be able to reject
it.

**Both hazards refused, on the target where the fallback is the only engine.**
The symlink destination is refused at exit 7 with the link intact and the
external file byte- and mtime-identical, and the FIFO is refused at exit 7 with
the FIFO intact. On this agent there is no rsync to fall back to, so these are
not an override being exercised: they are what every install here now does.

**What this target cannot show**, and its greenness makes it easy to miss: the
rsync side of the asymmetry. That rsync replaces a symlinked root-file
destination and leaves its target alone is asserted only in the RHEL capture,
which is also the only place both engines meet the same fixture.
