--- reading, added when the output was retained ---

This is the Debian half of the step 1 evidence, and it exists because the plan
requires step 1's cases to pass on both supported targets while this agent
measures an installer that has no engine selection. The code review's ruling was
to supply the candidate as a fingerprinted verification input rather than weaken
the criterion or pull step 5's delivery forward, and this is that run.

**Every selection here is cp, and that is correct rather than uninformative.**
rsync is absent, so it cannot be selected whatever the override says. What the
six cases prove on this target is the *reason* attached to each: `1` reports
`forced by CPLX_INSTALL_PKG_FORCE_CP=1`, and unset, `0`, `yes`, `true` and empty
all report `rsync not found on PATH`. A truthy-looking value is therefore not
silently reported as a forced fallback on the one target where the fallback will
matter most, which is what those five cases are for here.

**The unchanged call site still fails.** Every selection case exits 5 at the
mirror with no engine operating. That is the point of step 1 being a selection
step: the announcement moved, the behaviour did not. The `baseline no-rsync
mirror` case, run against the candidate rather than the published installer,
makes the same statement directly.

**Both ordering controls run here too.** `selection-no-discovery` refuses a trace
with no archive discovery marker; `selection-out-of-order` refuses one whose
selection line follows the marker. They are separate controls rather than one
composite so each failure reason is checked independently and each counts once.
An earlier body had only the first, which calibrates marker presence, leaving the
branch that implements Q06 unexecuted on both targets.

**What this run is not.** It is not delivery. The verification input sits in the
consuming project's `tools/`, which is not packaged; the Step 0 stage in the same
build still measures `$PREFIX/bootstrap/bin/install_pkg.sh`, the published
installer, at 12 cases and zero failures, so the baseline continues to describe
what CI actually runs. Shipping the fixed installer through the archive remains
step 5's obligation under Q05, and this stage does not discharge it. The
duplication is temporary and should be deleted when step 5 does.

**Fingerprints.** The installer is `312be8ae`, 535 lines, `fallback: yes`, equal
byte for byte to the staged cplx source, which is what stops a stale copy in this
repository passing silently. The harness whole-file digest `5c8ba2b0` pins this
capture to commit `7852d0c0`; the shared-body digest `65451888` is the value the
RHEL capture also reports, from the cplx file, so both targets ran the same code.

**Two things this target cannot show.** The rsync-selected trace form and the
forced divergence both require rsync, which this agent will never have; that is
the Q19 defect itself, not a coverage gap the harness can close. Their evidence
is the RHEL capture's.
