===== the envelope, and why there is nothing to produce =====

The envelope is two facts beside the declaration: the SHA-256 of
`closure-config.txt`, and the path and commit those bytes came from. Its
consumer is the Debian agent, which has no cplx and cannot compare the
declaration against anything, so the digest lets it detect a bundle that is
absent, truncated or replaced with garbage. It does not detect a careful edit,
and the checker prints that limit on every run.

So it is a COMMITTED FILE, `src/setups/env/closure/closure-envelope.txt`, beside
the declaration it describes. It travels with everything else and packaging
verifies the pair. The suite asserts that the committed digest is the committed
declaration's digest, so a declaration edited without its receipt is a failing
case rather than an archive carrying a receipt for bytes it does not hold.

===== what round 9 added, and what it measured =====

Three cases close the list this step has carried since round 6: an interruption
during the upload stream, a signal during cleanup, and a candidate pathname
offered where the descriptor belongs. No production file changed.

BOTH SIGNALS ARE REAL AND BOTH ARE AIMED AT A PHASE. The stub announces that
`upload_write` or `upload_abort` has been ENTERED and holds the run there, so
SIGINT arrives inside the phase under test rather than wherever a `sleep` left
it. The signal goes to the run's own process group, which `setsid` creates:
that is what Ctrl-C does, and it is the only delivery that reaches `cat`, `tee`
and the uploader subshell as well as the shell that traps them. Signalling the
shell alone would prove nothing, because bash defers a trap until the foreground
command completes, so the pipeline would run to the end and the transaction
would commit before the trap was consulted.

THE PATHNAME CASE IS PROVED BY WHAT WAS PUBLISHED. The expected digest handed in
is the real digest of the file that pathname names, so a handoff that reopened
the name would stream those bytes, match, commit and leave one public object.
Nothing public with a correct expected digest is the assertion; "it refused" is
not, because every refusal in that section shares a status.

THE CLEANUP CASE ASSERTS A RETAINED SCRATCH DIRECTORY, and that is the honest
statement of its lifetime rather than an exception carved out for convenience.
Cleanup disarms EXIT, INT, TERM and HUP on entry, so the signal that arrives
inside `upload_abort` ends the process there and the removal that follows the
abort never runs. The stage object the stub was told to destroy is present for
the same reason, and that is what places the signal inside the cleanup rather
than beside it. Nothing is public on either path.
