===== what the fixture engine had to learn for this step =====

The corpus gained EIGHTEEN rows and REVISED THREE, and the engine gained the two
version-record mutations they need. Nothing here rebuilds an ELF: a version need
and a version definition are fixed-size records pointing into `.dynstr`, so
`verneed-set` repoints the donor's own need at a provider and a node and adds the
matching DT_NEEDED, and `verdef-set` renames the donor's second definition. The
offsets come from readelf's own first column rather than from a layout guess.

ONE THING THE ENGINE GOT WRONG UNTIL THIS STEP, and it is worth the paragraph
because it was a fixture defect that read as a code defect. The name slots are
the last 256 bytes of `.dynstr`, and the corpus header called those bytes symbol
names "which nothing in this effort reads". On this host that is false: the
donor's VERSION DEFINITION names live there, and writing slot 1 renamed two
definitions and emptied a third. Step 3 never noticed because nothing read those
names. Step 4's reader does, and an object carrying a definition whose name
cannot be read is one it must refuse, so the first run of this suite reported
nine failures over a provider the checker was right to refuse.

The repair is in the engine and not in the reader: a generated object now carries
ONLY the version records its row asks for, and none of the donor's. Every donor
copy clears both version section counts, and the two version verbs set the count
they need back. That also makes every coherence count in this capture exact
rather than donor-dependent, and it is why step 3's trees now carry no version
records at all and its 124 cases are unchanged.
